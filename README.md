# Система управления банковскими картами

## 📌 Краткое описание проекта
Система предназначена для управления банковскими картами пользователей. Проект реализует создание, просмотр и управление картами, включая операции перевода денег между собственными картами пользователя. Для обеспечения безопасности используется шифрование данных, ролевой доступ и маскировка номеров карт.

## 🔗 Основные технологии
- Java 17+
- Spring Boot
- Spring Security (+JWT)
- Spring Data JPA
- PostgreSQL
- Liquibase (для миграций базы данных)
- Docker
- Swagger (OpenAPI для документации API)

## 🚀 Особенности системы
### Функционал
- Управление картами (создание, изменение статуса, удаление).
- Просмотр списка карт с фильтрацией и постраничной навигацией.
- Возможность переводов между собственными картами.
- Поддержка ролей (ADMIN и USER):
  * Пользователи видят только свои карты и могут запрашивать блокировку карты.
  * Администраторы имеют полный доступ ко всем картам и пользователям.

### Архитектурные решения
- RESTful API с использованием контроллеров Spring MVC.
- Роутинг запросов на уровне сервисов с применением принципов SOLID.
- Реализация валидации полей с проверкой формата номера карты и срока действия.
- Использование миграций базы данных с помощью Liquibase.

### Безопасность
- Авторизация с использованием токенов JWT.
- Ограничение доступа к ресурсам в зависимости от роли пользователя.
- Маскирование номеров карт перед выводом в интерфейс.
- Хэширование паролей пользователей.

## 🖥️ Локальная настройка и запуск
Для локальной настройки и тестирования приложения выполните следующие шаги:

1. Убедитесь, что у вас установлены Java 17+ и Maven.
2. Скачайте проект с репозитория.
3. Выполните команду сборки:
   ```bash
   mvn clean install
   ```
4. Проверьте конфигурационные файлы (`application.yaml`).
5. Используйте Docker Compose для развертывания баз данных и окружения:
   ```bash
   docker-compose up
   ```
6. Запустите приложение командой:
   ```bash
   java -jar target/app.jar
   ```

## 🔐 Авторизация и учётные записи

При первом запуске системы автоматически создаётся учётная запись администратора. Данные для входа:

- **Логин (username):** `admin`
- **Пароль (password):** (захеширован в базе данных; для тестирования используйте API‑запросы с токеном JWT)

### Важно
1. Пароль хранится в базе данных в зашифрованном виде (алгоритм BCrypt, `$2a$12$...`).
2. Для входа в систему:
    - Отправьте POST‑запрос на `/api/auth/login` с телом:
      ```json
      {
        "username": "admin",
        "password": "password"
      }
      ```
    - В ответе получите JWT‑токен, который нужно использовать в заголовке `Authorization: Bearer <токен>` для последующих запросов.
3. Для смены пароля администратора используйте API‑метод `/api/users/change-password` (требуется авторизация).

### Безопасность
- Не используйте учётную запись `admin` в продакшн‑среде без смены пароля.
- Для продакшна рекомендуется:
    - Изменить пароль через API.
    - Настроить LDAP/OAuth2 вместо локальной аутентификации.
    - Ограничить доступ к endpoint‑ам администрирования.
